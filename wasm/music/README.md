# music — заявки на треки из Яндекс Музыки

Автономный (standalone) wasm-плагин для Overlay Composer. Зритель погашает награду за баллы канала и вставляет ссылку на трек
(`https://music.yandex.ru/album/…/track/…`); плагин ставит заявку в очередь, аддон плеера забирает её, запускает трек и
подтверждает. Награда на Twitch **выполняется** (трек запущен) или **отменяется** (баллы возвращаются зрителю: ссылка не подошла,
очередь полна, плеер не смог запустить трек).

Разрешения: `storage` (очередь), `twitch.redemption` (события наград и смена их статуса).

## Установка

1. Скачайте `music.wasm` со [страницы релизов](https://github.com/compico/oc-plugins/releases) (теги `music-v<версия>`).
   Если нужно проверить файл — рядом лежит `music.wasm.sha256`.
2. Положите его в папку плагинов Overlay Composer — рядом с обычными плагинами (её открывает «Open folder» в окне «Standalone plugins…») — и нажмите «Rescan» там же.
3. Откройте в редакторе «Plugin store… → Standalone plugins…», найдите «Заявки на треки» и:
   - отметьте разрешения `storage` и `twitch.redemption`;
   - в настройках выберите награду из списка или нажмите «New reward…» и создайте её прямо там (название, цена, подсказка зрителю), затем «Save settings».

Награду нужно создавать именно через OC: Twitch разрешает менять статус погашения только тому приложению, которое награду создало
(награды, созданные в кабинете Twitch, в списке помечены «created elsewhere»). Для этого OC должен быть подключён к аккаунту стримера
с нужными правами Twitch.

## Виджеты

В «Add Source → Plugins» появятся два виджета (standalone). Интерфейс лежит в `ui/` и упаковывается в сам `music.wasm` при сборке.

- **Плеер с заявками** (460×400): карточка «сейчас играет» (обложка, название, исполнители, полоса прогресса) и ниже ближайшие заявки.
  Прозрачный фон — удобно для OBS. Данные о треке присылает аддон PulseRedeem (`POST /nowplaying`); если аддон молчит дольше
  20 секунд (PulseSync закрыт), виджет показывает «Ничего не играет». Для заявок известен только ID трека, названия подтягиваются лишь у играющей.
- **Очередь треков** (420×360): только список заявок, без плеера.

Имена зрителей и всё, что пришло от аддона, выводится как обычный текст. Обложка берётся только с `avatars.yandex.net`.

## Маршруты для аддона плеера

Все — `http://127.0.0.1:8000/plugins/music/api<путь>`, ответы JSON.

| Запрос | Что делает |
|---|---|
| `GET /next` | следующая заявка: `{"item": {id, user, trackId, albumId, url, …}, "resend": false}`; очередь пуста — `{"item": null}`. **Идемпотентный:** пока аддон не подтвердил старт или ошибку, повторный опрос отдаёт ту же заявку с `"resend": true` — аддон, перезапустившийся посреди трека, не теряет заявку и не пропускает следующую |
| `POST /started` `{"id": N}` | трек запущен → награда выполняется |
| `POST /failed` `{"id": N, "reason": "…"}` | запустить не удалось → награда отменяется, баллы возвращаются |
| `POST /nowplaying` | аддон присылает состояние плеера: `{trackId, title, artists[], cover, durationMs, positionMs, playing}`; пустой `trackId` — ничего не играет. Шлётся при смене состояния и раз в ~5 с. Хранится только в памяти |
| `GET /queue` | вся очередь с историей и поле `now` (состояние плеера или `null`) — для интерфейса |

`/nowplaying`: `400` — тело не объект или `trackId` не из цифр; длинные строки обрезаются, обложка не с `avatars.yandex.net` отбрасывается, позиция зажимается в `[0, durationMs]`.

Ошибки: `400` — тело не `{"id": N}`; `404` — нет такой заявки; `409` — заявка в неподходящем статусе (например, подтверждение неотданной);
`500 {"error":"storage error"}` — плагину не выдано `storage` или хранилище недоступно.

## Правила очереди

- Принимаются только ссылки на **трек** Яндекс Музыки: `https`, хосты `music.yandex.{ru,com,kz,by}`, путь `/album/<число>/track/<число>`.
  Ввод зрителя недоверенный: ID из произвольного текста не вытаскиваются, лишний текст вокруг ссылки — отказ.
- В ожидании не больше 100 заявок; помним последние 200, но не больше ~200 КБ состояния (у значения в хранилище OC лимит 256 КБ):
  при превышении срезаются самые старые завершённые заявки, ожидающие и отданные плееру не теряются. Повторная доставка того же
  погашения после переподключения игнорируется. Ввод зрителя сохраняется для показа в первых 200 символах.
- **Заявки персистентные:** очередь лежит в хранилище OC (SQLite приложения), перезапуск плагина или OC её не теряет;
  отданная, но не подтверждённая заявка после перезапуска уйдёт плееру повторно.

## Разработка

Логика очереди (`queue.go`) не зависит от ABI и SDK и тестируется обычным `go test`; `main.go` подключает её к хосту через
[`pkg/ocplugin`](https://github.com/compico/overlaycomposer/tree/main/pkg/ocplugin).

```
cd wasm/music && go test ./...        # тесты логики
node scripts/wasm.mjs build music     # из корня репозитория: vet, тесты, dist/music.wasm, упаковка ui/ (ocpack), метаданные из oc_meta
```

Размер `music.wasm` ≈ 5 МБ — это рантайм Go; на работу он не влияет, компиляция в OC при первом запуске занимает секунды и кэшируется.
Выпуск новой версии: поднимите `version` в `main.go` — после merge в `main` CI соберёт плагин и создаст релиз `music-v<версия>`.
Если менялся код, а версия осталась прежней, CI на PR упадёт с подсказкой.
